# Writing Artifacts

Owns docs, reports, handoffs, issue drafts, and standalone artifacts.

Goal: compact, source-backed artifacts for world-class expert readers.

- Expert reader: assume deep command of every named domain. Leave basics and ordinary implications unstated. Teaching enters scope only on explicit request.
- Anchors: details and caveats earn space by grounding a claim, premise, constraint, or final state. Use exact source anchors where useful.
- Repo truth: trust the reader to inspect code, diffs, tests, and history. Summarize code state at high level. Expand when explicitly asked or when a hidden fact is required to support the artifact.
- Native form: follow the expected shape of the artifact. Use prose, headings, lists, diagrams, snippets, or tables as the material earns them. Named concerns guide content without prescribing sections.
- Decision state: state the final in-scope decision. Include decision history only when explicitly asked.
- Task/spec: focus on intended outcome, contract, constraints, and proof bar. Include current implementation detail only where it changes these.
- Handoff: when writing a handoff, make continuation possible without chat. Give quick orientation, live blockers, proof state, and next action; point to the repo and durable artifacts for detail.
- Visual contrast: use diagrams for conceptual shape and snippets for concrete shape. Use either or both according to signal.
- External report: lead with behavior, timeframe, and evidence. Bound private detail and causal claims. Prescribe a next action only when proven.
- Truth repair: replace stale or misleading text before expanding coverage.

Complete when the intended expert can recover the artifact's final state, verify material claims from their anchors, and act within scope.
