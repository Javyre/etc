Kit reference

Components, and when each earns its place

Checked against brief.css and brief.js in this kit on 2026-09-28.

Bottom line

A page has one column, one accent, and no motion. Color means a verdict, a warning, or a highlight, and nothing else. Every block below exists because prose alone did a worse job in a real brief. If prose does the job, use prose.

1Prose, links, inline code

Body text is a serif at 17 px in a 45 rem column, about 75 characters per line. Headings, tables and chrome use the system sans. Links use the accent with a thin underline; a normal link looks like this, and path/to/file.rs:42 is a code reference link. Inline code sits on a faint card. A highlight is a soft amber marker in both themes.

Side note. With room in the gutters it sits in the right gutter; without room it drops inline, small and muted. Use it for an aside the reader can skip without losing the thread.

Keyboard: ← and → follow the pager. The section number next to each heading is its permalink.

2Callouts and verdicts

A callout is a neutral card with one colored rule and one colored label. The color names the kind; the card never changes, so a page with six callouts still reads as one surface.

Warning

A fact that changes what the reader does next. At most one or two per page.

In the seed
  • Claim 1 holds Evidence in one line, with a link.
  • Claim 2 partly What holds, what does not.
  • Claim 3 fixed at head The commit that fixed it.
  • Claim 4 wrong The correction and its proof.
  • Claim 5 unverified What evidence is missing.

Decision questions go on page 1 and each gets its answer somewhere in the set:

  1. Is the change safe to merge before the next release?
  2. Which of the seed's fixes can ship without a program upgrade?

3Source excerpts

Quote the few pieces of source that carry the argument: a constant, an enforcing check, a defining sentence. The caption links the exact lines at a pinned commit. The text is the source's own, from the file itself.

Syntax colors share one lightness and differ by hue: keywords in the accent hue, then strings, numbers, types, and macros; comments are muted. The highlighter only wraps text nodes, so <mark> and links inside the code survive.

4Pseudo stack traces

Use a trace when the point is control flow or causality. Hand-annotate with .k (frame), .c (aside), .w (cost), .b (failure), .o (success). Traces are never syntax-colored.

send_transaction(tx)
 ├─ blockhash = cache.get()              // cached up to 40 s
 ├─ rpc.send(tx)                          ok: signature
 └─ confirm(signature)
     ├─ poll getSignatureStatuses         ≈ 150 blocks until expiry
     └─ timeout                           panic: unwrap on Err

7Gap-fill and side notes

Background the reader may already know goes in a collapsed block. An expert skips it at no cost; a reader who needs it opens it.

Background: what a skipped slot is

A slot is a leader's time window. If the leader produces no block, the slot is skipped: slot numbers advance, block height does not.

Use at most two levels: the page and one collapsed block. Never nest them.

9Page chrome

  • Top bar. Stays in place. Shows the set, the current section when there is no map, the position, the tuning panel, and the theme (Auto, Light, Dark).
  • Map. With room in the gutters the contents list sits in the left gutter and marks the section you are reading; side notes sit in the right gutter. Without room the contents list stays at the top and notes sit inline.
  • Tune. The Tune button or the , key opens a panel that edits colors, type, layout and options for every page that uses the kit, in this browser, and exports them.
  • Resume. An unfinished page reopens where you left it. A page counts as read once its pager comes into view; the index then marks it read.
  • Reading time. Added to the first meta line.
  • Storage. Only these conveniences, in the browser: theme and tuning for every kit page, resume and read marks per set. Nothing leaves the machine.
