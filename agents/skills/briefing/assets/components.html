Bottom line

Every visible difference on a page names a kind of thing, one signal at a time. Color means a kind (a verdict, a warning, a link, a highlight) and nothing else. Each block below exists because prose alone did a worse job; if prose does the job, use prose. The reasons are in references/typesetting.md.

1Prose, links, inline code

Body text is a serif at 17 px in a 45 rem column, about 75 characters per line. Headings, tables and chrome use the system sans. All faces share the serif's x-height, so one size reads as one size in every face. Links use the accent with a thin underline; a normal link looks like this, and path/to/file.rs:42 is a code reference link. Inline code sits on a faint card. A highlight is a soft amber marker in both themes.

Inference. A run-in head opens a paragraph of a kind the reader scans for: Inference, Rule, Watch for. It is set in the sans, so it stays apart from a bold term in the serif. Line citations go in the source line that closes the block, not in the sentence. brief.css · brief.js

After a block that cannot hold a source line (a trace, a table, a figure without a caption), use <p class="cite"> right after it. The tuning panel can run source lines into the text in parentheses instead (cites).

Side note. With room in the gutters it sits in the right gutter; without room it drops inline, small and muted. Use it for an aside the reader can skip without missing the argument.

Keyboard: ← and → follow the pager. The section number next to each heading is its permalink.

2Callouts and verdicts

The bottom line is the one card on a page. A warning gets a rule in its kind's color; a closing list or ledger gets a plain rule. Labels are muted sans lines. A claim that holds needs no box, and an aside is a side note.

Warning

A fact that changes what the reader does next. Use it rarely.

In the seed
  • "Claim 1" holds Evidence in one line, with a link.
  • "Claim 2" partly What holds, what does not.
  • "Claim 3" fixed at head The commit that fixed it.
  • "Claim 4" wrong The correction and its proof.
  • "Claim 5" unverified What evidence is missing.

Numbered questions hang their labels in the margin:

  1. Is the change safe to merge before the next release?
  2. Which of the seed's fixes can ship without a program upgrade?

3Source excerpts

Quote the few pieces of source that carry the argument: a constant, an enforcing check, a defining sentence. The caption links the exact lines at a pinned commit. The text is the source's own, from the file itself.

Syntax colors share one lightness and differ by hue: keywords in the accent hue, then strings, numbers, types, and macros; comments are muted. The highlighter only wraps text nodes, so <mark> and links inside the code survive.

4Pseudo stack traces

Use a trace when the point is control flow or causality. Hand-annotate with .k (frame), .c (aside), .w (cost), .b (failure), .o (success). Traces are never syntax-colored.

send_transaction(tx)
 ├─ blockhash = cache.get()              // cached up to 40 s
 ├─ rpc.send(tx)                          ok: signature
 └─ confirm(signature)
     ├─ poll getSignatureStatuses         ≈ 150 blocks until expiry
     └─ timeout                           panic: unwrap on Err

6Tables

Numbers are tabular and right-aligned with td.num. Sizes of a change take two columns, + and −, with .add and .del spans, so every row keeps one line and the digits align. A wide table scrolls inside its own box; the page never scrolls sideways.

7Gap-fill and side notes

Background the reader may already know goes in a collapsed block. An expert skips it at no cost; a reader who needs it opens it.

Background: what a skipped slot is

A slot is a leader's time window. If the leader produces no block, the slot is skipped: slot numbers advance, block height does not.

Use at most two levels: the page and one collapsed block. Never nest them.

9Page chrome

  • Metadata. Opens every page: one row per key, keys muted. The rows run together and wrap between rows; a row marked .own keeps a line of its own. The tuning panel switches to one row per line (metaform).
  • Top bar. Stays in place. Shows the set, the current section when there is no map, the position, the tuning panel, and the theme (Auto, Light, Dark).
  • Map. With room in the gutters the contents list sits in the left gutter and marks the section you are reading; side notes sit in the right gutter. Without room the contents list stays at the top, notes sit inline, and the section name in the top bar opens the map as a drop-down. Map entries are short labels; the headings state the claims.
  • Tune. For the kit's maintainer, not for reading: the Tune button or the , key opens a panel that edits colors, type, layout and a few options for every page that uses the kit, in this browser, and exports them.
  • Resume. An unfinished page reopens where you left it. A page counts as read once its pager comes into view; the index then marks it read.
  • Reading time. Fills span.rt in the metadata block.
  • Storage. Only these conveniences, in the browser: theme and tuning for every kit page, resume and read marks per set. Nothing leaves the machine.
